# Протокол ручной проверки: контроль плана

Форма для сценариев, которые автотестом не берутся. Каждый пункт — то, что
проверяющий делает руками, и сценарий спеки, на который пункт отвечает.
Расписка в `MANUAL` действительна ровно настолько, насколько актуален этот
протокол: change, меняющий поведение, обязан пройти его заново.

**Что проверяем:** раздел «Контроль плана», capability `sales-plan-control`.

**Окружение прогона:** демо-стенд, 10 магазинов × 7 категорий, план на
сентябрь, рабочая модель `baseline-v3` с горизонтом 7 дней.

---

## 1. Единица измерения видна в рабочей таблице

Закрывает сценарий
`sales-plan-control/Единица измерения плана названа явно/Единица видна в рабочей таблице`.

- [x] 1.1 Открыть раздел с документом плана в штуках. Заголовок рабочей
      таблицы называет единицу — «шт.» — а не оставляет колонки безымянными
      числами.
- [x] 1.2 Свернуть окно до ширины ноутбука. Единица остаётся видимой:
      она в заголовке колонки, а не в подсказке при наведении.
- [x] 1.3 Выгрузить таблицу. Единица присутствует в шапке файла.

**Замечание прогона.** На ширине меньше 1280 px заголовок «Ожидаемый итог, шт.»
переносится на две строки и визуально сливается с соседним. Не блокирует:
единица читается. Заведена отдельная задача на верстку.

## 2. Список приоритетов читается с экрана

Закрывает сценарий
`sales-plan-control/Ранжирование строк по вкладу в разрыв/Список приоритетов читается с экрана`.

- [x] 2.1 Загрузить план на полный разрез (70 строк на стенде; проверка
      повторена на синтетическом наборе в 10 тыс. строк). Открыть список
      приоритетов.
- [x] 2.2 Первые 20 строк видны без прокрутки на экране 1920×1080.
- [x] 2.3 Дополнительная фильтрация для этого не требуется: список открыт
      уже отсортированным по абсолютному вкладу в разрыв.
- [x] 2.4 Строка с разрывом −3% при плане 10 000 стоит выше строки с −50%
      при плане 10. Это тот же порядок, что проверяет автотест
      `test_priority_is_absolute_contribution`, — здесь проверяется, что он
      виден глазами, а не только в ответе ручки.

**Замечание прогона.** На 10 тыс. строк первая отрисовка занимает ≈1,8 с.
Приемлемо, отдельной задачи не заводилось.
